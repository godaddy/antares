## Features

- **Composable interior**: Compose `Label`, `Input` or `TextArea`, `Text slot="description"`, and `FieldError`. Omitting `Group` leaves the control as a direct field child with box chrome. Use an explicit `Group` for controls or adornments
- **Adornments**: Fixed text or icons before or after the input (e.g. `$`, `.00`, `px`) are composed inside `Group`, positioned by source order
- **Controls**: A `Button slot="control"` beside the input is an interactive affix; it picks up field chrome from context
- **Controlled or uncontrolled**: Use `value` and `onChange` for controlled state, or `defaultValue` for uncontrolled
- **Multiline**: Compose a `TextArea` instead of an `Input` for multiline entry
- **Validation states**: Use `isInvalid` with a `FieldError` and `isDisabled` for validation and disabled state

## Sizing and typography

TextField consumes explicit size, then interface size, then `md`, and provides that size to its parts.
Label uses the shared label treatment. Input, TextArea, and input-group icons share input typography.
Descriptions accept Text or Detail; explicit child typography and layout props win.

| Field size | Label / input tier | Supporting Detail tier | Input padding | Minimum input height | Gap |
| --- | --- | --- | --- | --- | --- |
| `sm` | `sm` | `md` | 1 GU | 2rem | `xs` |
| `md` | `md` | `lg` | 2 GU | 2.5rem | `sm` |
| `lg` | `lg` | `xl` | 3 GU | 3rem | `md` |

These mappings are provisional for pilot review. Supporting text defaults to passive color; errors use
critical color. Owned buttons inherit the field size. Select still supports only `sm`/`md`, so a Select
composed into a large field uses its current medium treatment until its later adoption.
Input `size` remains the native character-width attribute, independent of interface sizing.

## Props

```tsx
<TextField>
  <Label />
  <Input />
  {/* or <TextArea /> */}
  {/* or <Group><Input /></Group> for adornments or a control */}
  <Text slot="description" />
  <FieldError />
</TextField>
```
