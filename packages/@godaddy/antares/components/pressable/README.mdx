## Features

- Adds accessible press behavior to an existing visual component.
- Applies interaction states directly to the child without adding a wrapper element.
- Supports pointer, touch, and keyboard interactions through React Aria.
- Preserves the child's layout, shape, and visual styling.

## Customization

Use `Pressable` when an existing visual component or layout surface needs press behavior while keeping its own DOM element, layout, and styles. The child must be a single element that forwards its ref and accepts the props applied by React Aria.

Use `Button` when you need a standard button control with button-specific sizing, layout, and visual variants.

Pass `onPress` for the action instead of wiring separate pointer and keyboard handlers:

```tsx
<Pressable aria-label="View account summary" onPress={handlePress}>
  <Box role="button" padding="md" rounding="md" elevation="card">
    Account summary
  </Box>
</Pressable>
```

## Accessibility

`Pressable` accepts the React Aria press props, including `onPress`, `onPressStart`, `onPressEnd`, `onPressUp`, and `onPressChange`.

Use a semantic interactive element when possible. For a non-semantic child such as `Avatar` or `Box`, provide an appropriate interactive role and an accessible name:

```tsx
<Pressable aria-label="View account summary" onPress={handlePress}>
  <Box role="button" padding="md">
    Account summary
  </Box>
</Pressable>
```

Do not add `role="button"` to a native `<button>` or `<a>` unless you intentionally need to change its semantics. Use a dedicated semantic component such as `Button`, `LinkButton`, `Menu`, or `ToggleButton` when that control's meaning is known.

## Best Practices

- Prefer a native interactive element or a semantic Antares component when the interaction meaning is known.
- Use `Pressable` for custom visual surfaces that need a press interaction without an additional DOM wrapper.
- Give every pressable control an accessible name with visible text, `aria-label`, or `aria-labelledby`.
- Avoid nesting interactive elements inside the child passed to `Pressable`.
- `Pressable` automatically applies `[data-focus-visible]` and `[data-disabled]` attributes to the child. Ensure the child component styles these states appropriately if it overrides the default `Pressable` styles.
- When `isDisabled` is true, `Pressable` suppresses all pointer and keyboard interactions.

## Troubleshooting

- If React Aria warns that the child is not interactive, add an appropriate role and ensure the child forwards its ref and props.
- If `onPress` does not fire, confirm that the child is a single focusable element and is not disabled by another component.
- If a custom component loses interaction props, update it to forward `className`, ref, ARIA attributes, and event handlers to its DOM element.
