`MenuTrigger` wraps a trigger element and a `Popover` containing `Menu`. The menu is fully keyboard-navigable, supports typeahead search, and handles open/close state automatically. The trigger applies `hideArrow` and card styling to all popovers, including nested submenus.

## Features

- **Trigger and popover**: `MenuTrigger` wraps any trigger and opens a `Popover` with automatic card styling and hidden arrow. Use for desktop; use `Drawer` for mobile.
- **Menu title and groups**: Place an optional `Heading` as a sibling to `Menu` (not `slot="title"`). Use `MenuGroup` + `Header` + `Heading` for section labels; group headings are presentational.
- **Composable rows**: Each `MenuItem` renders a string label or composed content (icons, checkboxes). Use render props (`isSelected`, `selectionMode`) and pass `textValue` for typeahead.
- **Single or multiple selection**: Set `selectionMode="single"` or `"multiple"` on `Menu` or per-`MenuGroup`. Use controlled state or `defaultSelectedKeys` for uncontrolled menus.
- **Separators and submenus**: `Separator` divides items. `SubmenuTrigger` nests a `Popover` + `Menu` for hierarchies.
- **Popover or drawer**: Open from `MenuTrigger` for positioned overlays, or place `Menu` in a `Drawer` for full-screen/mobile.

## Accessibility

### Keyboard

| Key                  | Action                                       |
| -------------------- | -------------------------------------------- |
| `Enter` / `Space`    | Activates the focused item                   |
| `Arrow Up` / `Down`  | Moves focus between items                    |
| `Home` / `End`       | Jumps to the first or last item              |
| `Arrow Right`        | Opens the submenu (if present)               |
| `Arrow Left`         | Closes the submenu and returns focus         |
| `Escape`             | Closes the menu (or submenu)                 |
| Typeahead (letters)  | Jumps to the item matching the typed letter  |

### ARIA

- **Menu accessible name**: Set `aria-label` on the `<Menu>` to name the list (e.g., "Actions", "Share with"). This is separate from any `Heading` title in the popover.
- **Roles**: Single-select items use `menuitemradio`; multiple-select use `menuitemcheckbox`. Unselectable items use `menuitem`.
- **Selection indicators are decorative**: A checkbox, radio check, or chevron-right icon is purely visual. The item owns the `aria-checked` state.
- **Group headings**: The group `Heading` receives `role="presentation"` automatically and acts as a label for the group, not a real heading level.

## Best Practices

- **Title placement**: Place an optional `Heading` as a sibling to `Menu`, not wrapped inside (do not use `slot="title"`; see "Title and groups" example).
- **Menu name**: Set `aria-label` on `<Menu>` to name the list ("Actions", "Share with", "Theme").
- **Stable IDs**: Give each `MenuItem` a unique `id` for React tracking across re-renders.
- **Typeahead**: For composed labels (icons, checkboxes), provide `textValue` to `MenuItem` for typeahead search.
- **Selection modes**: Set `selectionMode` on `Menu` (all items) or per-`MenuGroup` (only group). Use controlled state for tracking.
- **Submenus**: Use `SubmenuTrigger` with `chevron-right` icon. Keyboard navigation is automatic.
- **Mobile**: Replace `MenuTrigger` + `Popover` with `Drawer` on narrow viewports; reuse the same `Menu`.
- **Avoid complex content**: Forms, date pickers, and multi-line content belong in a separate overlay, not in menu items.

## Props

```tsx
<MenuTrigger>
  <Button />
  <Popover>
    <Heading />
    <Menu>
      <MenuItem />
      <Separator />
      <MenuGroup>
        <Header>
          <Heading />
        </Header>
        <MenuItem />
      </MenuGroup>
      <SubmenuTrigger>
        <MenuItem />
        <Popover>
          <Menu>
            <MenuItem />
          </Menu>
        </Popover>
      </SubmenuTrigger>
      {/* ... */}
    </Menu>
  </Popover>
</MenuTrigger>
```
