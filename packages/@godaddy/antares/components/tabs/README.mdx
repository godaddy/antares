## Features

- Accessible Tabs semantics powered by React Aria Components.
- Underline and Manila visual treatments.
- Controlled and uncontrolled selection.
- Automatic horizontal overflow controls that move one tab at a time.
- Localized labels for the automatic overflow controls.

## Installation


## Accessibility

Tabs require an accessible label on `TabList`. Use the keyboard to move between tabs with the arrow keys. Disabled tabs are skipped. Use `keyboardActivation="manual"` when focus should move independently of selection.

`overflowLabels.previous` and `overflowLabels.next` are required because the overflow controls are interactive and must be announced with localized action labels.

`TabList` must be rendered inside `Tabs` and must provide `aria-label` or `aria-labelledby`. Each `Tab` must have an `id` that matches its associated `TabPanel`.

## Customization

The component exposes state through data attributes:

- `Tabs`: `data-design="underline"` or `data-design="manila"`.
- `Tab`: `data-selected`, `data-hovered`, `data-pressed`, `data-focus-visible`, and `data-disabled`.
- `TabPanel`: `data-inert` when a force-mounted inactive panel is not interactive.

Use these attributes to extend styling without replacing the accessibility behavior supplied by React Aria Components.

## Best Practices

- Use Tabs for peer panels on the same page and URL.
- Keep the number of tabs small enough for users to understand the available sections.
- Do not use Tabs for primary application navigation or route changes.
- Do not render a standalone `Tab`; compose it inside `Tabs` and `TabList`.
