Use `ModalTrigger` to wire a trigger element (typically a `Button`) to a `Modal`. The Modal is **composition-first**, modeled on React Aria / Spectrum's `Dialog`: it owns only the overlay, container, dialog shell, and scroll layout - it does not decide the interior. You author the content by composing the shared containers (`Header`, `Content`, `Footer`, `ButtonGroup`) plus `Heading slot="title"` and `CloseButton`. The Modal styles each region via context, and React Aria wires the title (`aria-labelledby`) and the close behavior, so you only tag the pieces. A `Modal` with no children renders an empty dialog.

The dialog is a scroll-aware flex column: the `Content` region scrolls while the `Header` and `Footer` stay pinned. That scroll layout is owned by the Modal (a height-constrained container), not by the generic containers, so the same `Content` does not scroll when used elsewhere.

```tsx
<ModalTrigger>
  <Button variant="primary">Open modal</Button>
  <Modal>
    <Header>
      <Heading slot="title">Delete file?</Heading>
      <CloseButton />
    </Header>
    <Content>This action cannot be undone.</Content>
    <Footer justifyContent="end">
      <ButtonGroup>
        <CloseButton variant="secondary">Cancel</CloseButton>
        <Button slot="close" variant="critical">
          Delete
        </Button>
      </ButtonGroup>
    </Footer>
  </Modal>
</ModalTrigger>
```

## Accessibility

### Keyboard interaction

| Key           | Action                                                         |
| ------------- | -------------------------------------------------------------- |
| `Tab`         | Moves focus to the next focusable element inside the modal     |
| `Shift + Tab` | Moves focus to the previous focusable element inside the modal |
| `Escape`      | Closes the modal (when dismissable)                            |

### ARIA

- `role="dialog"` is applied automatically by the underlying React Aria `Dialog`
- A `Heading slot="title"` is rendered as a heading and linked to the dialog via `aria-labelledby`
- The `CloseButton` is rendered with `aria-label="Close"` and picks up the close behavior via `slot="close"`
- Focus is trapped within the modal while open and returned to the trigger on close

## Best Practices

- Always include a `Heading slot="title"` so the dialog has an accessible name; otherwise pass `aria-label`/`aria-labelledby` on `<Modal>`
- Pair every footer action with `slot="close"` (or use `CloseButton`) when it should dismiss the modal
- Set `isDismissable={false}` for required confirmations the user must explicitly answer
- Group footer actions in a `ButtonGroup` for consistent spacing and alignment
